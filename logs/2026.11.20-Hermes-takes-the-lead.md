## Testing the Hermes and Pi Handoff

I installed Pi as a lightweight coding harness and initially connected it to GitHub Copilot, which gave me a separate usage allowance. I had also tried local models, but they were too slow on my hardware for the kind of sustained coding and tool use I wanted.

I was already giving Hermes the design and deciding what belonged in each sprint. The change was to let Hermes lead the implementation by assigning work, reviewing it, and sending corrections back while Pi wrote the code. That also gave me a way to use two agents on the same project without handing them overlapping assignments.

The first test was a small Python terminal calculator. Pi wrote the application, tests, and README. Hermes reviewed the work, ran ten passing tests, and checked the calculator interactively, including whether it recovered after invalid input and division by zero. Hermes then saved the workflow for reuse.

I gave them a second pass covering calculation history, a Clear History option, and more readable terminal spacing. The expanded suite passed 34 tests. Hermes checked that successful calculations appeared in order, failed operations stayed out of the history, and both canceling and confirming a clear worked as intended.

They also built a small local Sprint Board with **To Do**, **Doing**, and **Done** columns. It was usable in about five minutes. I put a `Nexus Sprint 5` card in **Doing** and moved on to the real test.

## Sprint 5 – Human-to-Human Messaging

Sprint 5 was the first Nexus sprint I ran with Hermes leading and Pi implementing. I used GPT-6 Sol through OpenAI for this run and kept GitHub Copilot available in Pi as a backup.

When I checked partway through, Hermes reported three of six tasks complete and was reviewing the changes. The sprint had started without a visible terminal, so I had to ask what was happening. Going forward, I want a terminal or live log open by default so I can see when Hermes hands off work, when Pi is running, and when something goes back for correction.

The final report came through Discord. Pi needed two rounds of corrections. Hermes caught an authorization issue in direct messages where the server needed to verify the exact pair of participants. On the frontend, denied access needed to clear cached private content and prevent a delayed response from bringing it back. The review also caught issues involving duplicate display names and conversation context on mobile.

Hermes reported that the backend and frontend reviews passed after the corrections, followed by final verification. **The sprint was ready for my review, with the merge into `main` awaiting my approval.**

The run used about 2–3% of my allowance after roughly half an hour and about 15% by the final report. A previous run using Astra directly through Hermes had used more than half in less than an hour. That comparison reflects a different model and workflow, but it gives me a practical baseline for future sprints. I also noticed that Reeba’s fans were considerably quieter during this run.

## Nexus, MCP, and Agent Permissions

I started thinking about whether Nexus itself should become an MCP server for AETHER. The design I settled on was to make Nexus MCP-compatible and keep the MCP server separate.

I want agents to interact with services through Nexus so I have a place to see which agent requested an action, which service it wanted to use, and what was approved. The MCP server would expose the tools the agents can use. Nexus would provide the interface for managing service permissions, reviewing requests, and recording the outcome.

I want manual approval for service actions at first. For periodic checks, I can ask Mira to inspect parts of the lab and bring me recommendations. I can revisit limited autonomy once I have a better sense of what the agents ask for, how those actions behave, and what they cost to run.

The Hermes–Pi handoff also exposed a less visible problem. Two independent harnesses need access to the same project context. I want Nexus to give them a common place to find repository references, design notes, task assignments, and approved decisions. Git can continue to hold the source and change history, while BookStack remains the place for current AETHER documentation.
